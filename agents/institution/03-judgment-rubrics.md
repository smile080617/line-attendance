# 03 · 判斷力外化：rubric 與 checklist（harness 中立）

這些是把「強模型的判斷」寫成弱模型可執行的判定規則。每條附一正例一反例。
不綁定任何平台語法；「升級」「派驗證 agent」的具體操作方式見 02 與 04。

## Rubric 1：何時升級模型

逐項檢查，任一命中即升級：
- [ ] 便宜檔在同一子任務已錯 1 次？（升中階）
- [ ] 中階在同一子任務已連錯 2 次？（帶完整失敗軌跡升頂級）
- [ ] 任務含以下任一關鍵性質：規格模糊需要詮釋、跨多檔的架構取捨、對外發布的文字、
      安全／金流相關判斷？（這類直接從中階起跳，卡住即升頂級，不等錯兩次）
- [ ] 反向檢查：失敗原因是環境問題（缺套件、權限、網路）？→ **不升級**，升級無效。

✅ 正例：Haiku 級改一個正則改錯了一次。第二次交給 Sonnet 級，交辦包附上錯誤輸出
與三組「輸入→期望輸出」樣本。（錯一次就升，且附了軌跡）
❌ 反例：測試因為 `ModuleNotFoundError` 失敗，直接升 Opus 級重跑一次。
（環境問題，升級後照樣失敗，白燒頂級額度）

## Rubric 2：何時算真的完成

全部打勾才能回報「完成」：
- [ ] 任務卡上的驗收條件逐條核對，每條有證據（命令＋輸出，或 檔案:行號）。
- [ ] 實際執行過驗證命令並貼出輸出；無法執行驗證的改動，明寫「已修改，未實測」。
- [ ] diff 範圍 ⊆ 任務卡範圍；多改的東西要嘛移除、要嘛在回報中說明並標明未被要求。
- [ ] 產出裡沒有殘留 TODO、佔位符、「待補」字樣（除非驗收條件本來就允許）。
- [ ] 過程中踩到的雷已按 05 格式寫進 lessons.md（沒有就跳過）。

✅ 正例：「驗收 1：`npm test` 全綠（輸出貼於 logs/x.txt）；驗收 2：index.js:214 已改用
新參數。完成。」
❌ 反例：「我已經修好了打卡半徑的問題，應該可以用了。」（沒有命令、沒有輸出、
沒有位置——這叫「已修改，未驗證」，不叫完成）

## Rubric 3：何時停下來問使用者

**要問**（任一命中就停）：
- [ ] 動作不可逆或對外可見：刪資料、force push、寄信、發文、開 PR（若未被要求）、部署。
- [ ] 規格有兩種以上合理解讀，且選錯的重工成本 > 30 分鐘。
- [ ] 發現任務的前提本身是錯的（要改的東西不存在、需求與現況矛盾）。

**不要問**（自主決定，事後回報即可）：
- 可逆且在任務範圍內的實作選擇：命名、內部結構、做事順序、用哪個既有函式。
- 「要不要我繼續？」「我可以開始了嗎？」——永遠不問，直接做。

✅ 正例：「你要我改的 `checkRadius()` 在 main 已被刪除、邏輯併入 `verifyLocation()`。
改哪個？(a) 在 verifyLocation 內改 (b) 恢復 checkRadius。建議 a。」（前提變了，停下問，
且附選項與建議）
❌ 反例：「我打算先改 index.js 再跑測試，這樣可以嗎？」（可逆、在範圍內，不該問）

## Rubric 4：方向錯訊號——換路，而不是重試

出現任一訊號，立即停止重試：
- [ ] 同一個錯誤訊息第 3 次出現。
- [ ] 每修一個錯就冒出一個新錯，已連鎖 3 層。
- [ ] diff 持續變大，但驗收條件的打勾數沒有增加。
- [ ] 發現自己在改與任務卡無關的檔案。

換路動作（照順序做）：
1. 停手。回滾前先看 `git status`：未 commit 的修改一律先 `git stash` 保留，
   禁止直接 checkout 丟棄；若回滾會永久丟失任何內容，那就是不可逆動作，照 rubric 3 先問使用者。
2. 用 5 行寫下：已試的路、每條死在哪。
3. 選一條**不同**的實作路線（換工具、換切入點、縮小範圍），或按 rubric 1 升級，
   或按 rubric 3 問使用者。禁止原路第三次。

✅ 正例：改 A 檔引發 B 檔測試掛、修 B 又掛 C——停，回滾，改成「先加相容層再分兩步遷移」。
❌ 反例：同一個 type error 連續五輪微調重跑，每次只改一兩個字。（第 3 次就該停了）

## Rubric 5：品質底線怎麼驗

按產出類型選最低標準（可加碼、不可低於）：
- 檔案／設定改動：派 fresh agent 只憑「路徑＋驗收條件」read-back 核對。
- 程式碼：既有測試全綠；沒測試則實跑主流程一次並貼輸出。
- 文件／指令檔：讓 fresh agent 讀完後回答「這份文件要你做什麼、第一步是什麼」，
  答不出或答錯＝文件不合格，改到能答對。
- 高風險判斷：第二意見（另一供應商模型）或 3 候選＋評審擇優。

✅ 正例：改完 CLAUDE.md 後，派一個沒參與撰寫的 agent 讀它，問「你會先讀哪個檔？」
答對路由才算過。
❌ 反例：自己寫完自己讀一遍覺得通順就算驗證。（作者盲區：自驗只能算 smoke test）
