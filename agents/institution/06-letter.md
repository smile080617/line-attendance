# 06 · 給未來 session 的信

寫於 2026-07-04，由建立這套制度的 session 留下。讀者是三個 harness 上的任何模型
（多半是 Sonnet／Haiku／GPT-5.4-mini 等級）。這封信講三件事：沒被問到但最重要的事、
這套制度會怎麼壞、以及哪些產出信心最低。

## 三件使用者沒問、但最重要的事

1. **制度的執行率比制度的內容重要。** 這套檔案寫得再好，弱模型不會「自願」去讀分冊。
   它能運作全靠兩個機械設計：core.md 常載（索引檔第一行就指向它）、驗收條件可機械
   判定。所以最大的單點風險是「索引檔根本沒被裝進使用者本機的三個 harness」——
   如果你是回到本機後的第一個 session，先確認 05 的首次遷移清單做了沒；沒做，
   其他一切都是擺設。

2. **這個 repo（line-attendance）只是宿主，不是家。** 制度是使用者級資產，長期應搬到
   專用 repo（步驟見 `agents/README.md` 末段）。在那之前：line-attendance 的任何協作者
   或部署流程都不該碰 `agents/`；反過來，制度檔案也永遠不要引用打卡系統的程式碼。
   兩者只是同住，沒有依賴。

3. **省額度的真正槓桿是「失敗軌跡」和「跨供應商第二意見」，不是模型檔位本身。**
   帶完整失敗軌跡的一次升級，幾乎總是比便宜模型盲目重試三輪更省。而使用者同時有
   Claude／Codex／Hermes 三家，等於免費擁有跨供應商評審團——高風險判斷拿去另一家
   覆核的價值，遠高於在同一家內升一級。這是三 harness 並用的最大紅利，別浪費。

## 這套制度最可能的退化方式與預防

1. **三份索引漂移（最可能）。** 某個 session 圖方便把新規則直接寫進 CLAUDE.md 或
   AGENTS.md，三個月後三份索引各自長出互相矛盾的規則——正是本制度要消滅的原病。
   徵兆：索引檔行數增長。預防：權限表禁止弱模型改索引檔＋`agents/verify.sh` 月檢。
   你現在就可以跑一次 verify.sh，30 秒。

2. **記憶不回寫、正本變空殼。** Claude 的 auto-memory 與 Codex 的 memories 會自動累積，
   很舒服，於是教訓留在各 harness 快取裡，lessons.md 三十天沒有新條目——但你明明
   踩過雷。判準就是這個：踩過雷而 lessons.md 沒長，制度就在死去。預防：05 的月度
   搬運是例行任務，不是建議。

3. **型號表過期變成毒藥。** 弱模型最容易照抄 02 的型號表而不看「以當下 /model 清單
   為準」那行。型號不存在時：權限表允許你查證後自行更新型號格——這是少數你可以
   自己動正本的地方，動了要記 lesson。

4. **制度膨脹到沒人讀。** 每次「補充一點」都合理，加總起來就是死亡。行數上限
   （索引 ≤150、core ≤150、lessons 300 行觸發精簡）是硬規則，超了就精簡，
   不要用「這條很重要」豁免。

## 誠實條款：這次哪些產出信心最低、為什麼

按信心由低到高：

1. **Hermes 相關的一切（最低）。** 使用者沒有確認 Hermes 是哪個產品（選了「其他」但
   未填名稱）；我以高相似度暫定為 Nous Research `hermes-agent`，且其資料來自 GitHub
   上的 docs 檔而非官方站（官方站對查證工具回 403）。02 的 Hermes 欄、AGENTS.md 的
   Hermes 區塊，全部應視為「合理猜測」。**第一個在 Hermes 上跑的 session 應該做的事：
   核對身分，錯了就照 adapters/hermes-notes.md 的填寫指引重寫該區塊。**

2. **Codex 的 Memories 機制**（`~/.codex/memory/`、`generate_memories` 等 config key）
   來自第三方部落格，未在 developers.openai.com 直接證實。用之前先 `codex --help`
   或查官方 config 文件核對。

3. **Codex 型號細節。** GPT-5.5／GPT-5.4-mini 有官方來源，但「5.2/5.3-Codex 淘汰時程」
   部分來自非官方轉述，且新安裝的預設模型是什麼未能確認。以 `/model` 實際清單為準。

4. **跨 harness 分工表（02 末段）。** 基於各家機制的推理，沒有經過使用者實際工作流
   驗證。用兩週後值得回頭修訂。

5. **安全路由額度問題。** 「被導向 Opus 4.8 的請求是否消耗本窗額度」查不到官方說法，
   標未確認；建議使用者到 claude.ai 的 usage 頁實測。

6. **模糊題與品味判斷補不了**（誠實條款重申）：這套制度能把「可拆解、可驗證」的工作
   做到接近強模型水準；但規格模糊、審美取捨、政治敏感的判斷，弱模型＋rubric 只能
   做到「知道自己該停下來問」。遇到就升級、問外部第二意見、或明說做不到——
   rubric 3 的門檻就是為此而設，不要試圖用流程繞過它。
