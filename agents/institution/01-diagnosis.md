# 01 · 快速診斷：最漏 token、最易失焦、最易出錯的地方與修法

讀者是弱模型：每條修法都是可直接照做的動作，不是原則宣示。
「共通」= Claude Code / Codex CLI / Hermes Agent 三家都會犯；專屬項會標明 harness。

## 一、最漏 token（共通，三家合併）

**#1 無目標整檔閱讀與重複閱讀。**
症狀：把整個大檔讀進 context、或同一檔案讀第二次以上。
修法（照做）：
1. 讀檔前先寫一句「我要找 ___」。寫不出來就不准讀，先用 grep/搜尋。
2. 只讀命中行前後約 30 行；需要更多再擴一次，最多擴兩次。
3. 需要記住的內容，第一次讀到就抄進任務卡或筆記檔，之後查筆記不重讀原檔。

**#2 把長輸出倒進主對話。**
症狀：測試輸出、log、整包 diff、網頁全文直接貼進對話。
修法：長輸出一律導到檔案（如 `logs/test-run.txt`），主對話只留「結論 + 檔案路徑 +
關鍵 3 行」。派出去的 agent 也照此回報（回報合約見 02）。

**#3 用頂級模型做搬運工作。**
症狀：主線模型自己掃 repo、批次改 20 個檔、逐檔驗證。
修法：凡是「步驟能寫清楚」的工作就交給便宜檔位（見 02 的三檔位表與 04 的範本）；
主線只寫交辦包和讀結論。

## 二、最易失焦（共通）

**#1 長任務中途忘記原始驗收條件。**
症狀：做到第 5 步時開始解一個使用者沒要求的問題，或範圍悄悄擴大。
修法：開工先寫 3 行任務卡（目標／驗收條件／不做什麼）存檔；每完成一步回讀一次；
發現手上動作對不上任務卡任何一行，立刻停手，回到卡上的下一步。

**#2 錯誤處理歧途。**
症狀：遇到環境錯誤（缺套件、權限、網路）後，花大量回合修環境，忘了本來的任務。
修法：環境問題修 2 次修不好，就把「症狀 + 已試過什麼」記進任務卡，改走替代路線
（換工具、mock、標註未驗證），不要無限深入。

**#3（Claude Code 專屬）context 壓縮後遺忘。**
症狀：長對話被自動摘要後，忘記之前的決策與檔案位置。
修法：重要決策、關鍵路徑（檔案:行號）隨做隨寫進任務卡檔案，不依賴對話記憶；
壓縮後第一件事是回讀任務卡。

**#3'（Codex CLI 專屬）單線程誘惑。**
症狀：因為沒有自動 subagent，就什麼都自己做，一路做雜活導致主線失焦。
修法：Codex 的 subagent 只在明確要求時才生效——交辦時明說
「spawn a subagent using gpt-5.4-mini to …」；或另開低成本 session（見 02）。

## 三、最易出錯（共通）

**#1 幻覺式完成：宣稱做完但沒驗證。**
修法：回報「完成」之前，必須貼出「執行了什麼命令、看到什麼輸出」；
沒有可執行的驗證（例如純文案改動）就明寫「已修改，未實測」。

**#2 編造事實：型號、API、路徑、旗標憑印象填。**
修法：凡是可查證的事實（模型 ID、CLI 旗標、檔案路徑、函式簽名），先查再寫；
查不到就寫「待使用者填寫／未確認」。寧可留空，不可填錯。

**#3 改壞既有行為（迴歸）。**
修法：改任何既有檔案前先備份或確認在 git 管控下且工作區乾淨；
改完跑該 repo 既有的測試／lint；沒有測試就至少實跑一次受影響的流程，
並在回報中寫明測了什麼、沒測什麼。

**Hermes 專屬備註**：Hermes Agent 的身分尚未由使用者確認（暫定為 Nous Research
`hermes-agent`，它會自動注入 AGENTS.md/SOUL.md/MEMORY.md）。在未確認前，
Hermes 上只套用本檔的「共通」條目；專屬條目待使用者確認後補寫（見 06）。
