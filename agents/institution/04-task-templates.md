# 04 · 任務交辦 prompt 範本（harness 中立）

用法：挑對應範本 → 填空 → 用下方「派發方式」發給便宜檔位。範本內文不含任何平台
專屬語法，三個 harness 通用。填空原則：驗收條件必須可機械判定；回報格式必須照
02 的回報合約。

## 派發方式（三個 harness 各自怎麼把範本發出去）

- **Claude Code**（有原生 subagent）：主線直接派 subagent，指明便宜模型
  （例：Explore 或 general-purpose agent，`model: haiku`；需要寫檔的任務用
  general-purpose，`model: sonnet`）。範本全文放進 subagent 的 prompt。
- **Codex CLI**（subagent 需顯式喚起）：二選一——
  (a) 在 session 內明說「Spawn a subagent using gpt-5.4-mini to do the following: …」；
  (b) 另開低成本 session：`codex --model gpt-5.4-mini "＜貼範本全文＞"`，
  跑完只把結論帶回主線 session，然後關掉。
- **Hermes（暫定）**：`hermes -m ＜便宜模型，待使用者填寫＞ "＜貼範本全文＞"`，
  或用 `hermes kanban` 派工。未確認前也可退回 (b) 式：開新低成本 session 貼範本。

---

## 範本 1：搜尋／定位

```
任務：在 ＜repo／目錄＞ 找出 ＜要找什麼，一句話＞。
動機：＜為什麼要找，讓你能判斷邊角案例＞。
範圍：只看 ＜路徑／檔案類型＞；不要讀完整檔案，用搜尋定位後只讀命中段落。
驗收條件：
- 列出所有相關位置，格式「檔案:行號 — 一句話說明」。
- 對每個位置標注「確定相關／可能相關」。
- 若找不到，回報你搜過的 3 組以上關鍵字與範圍，不要只說「沒找到」。
回報格式：結論 ≤10 行 ＋ 位置清單。不要貼程式碼全文。
```

## 範本 2：實作

```
任務：＜做什麼，一句話＞。
動機：＜為什麼＞。
範圍：只改 ＜檔案清單＞；「不做什麼」：＜明列，例如不動 API 介面、不加新依賴＞。
做法提示：＜已知的正確方向或步驟；沒有就寫「自行規劃，先列步驟再動手」＞。
驗收條件：
- ＜命令＞ 執行後輸出 ＜期望結果＞。
- ＜檔案＞ 必須包含／不再包含 ＜內容＞。
- 既有測試／lint 全綠（命令：＜cmd＞）。
回報格式：驗收逐條 ✅/❌ ＋ 改動檔案清單（檔案:行號）＋ 執行過的驗證命令與關鍵輸出。
無法驗證的部分明寫「已修改，未實測」。錯 2 次就停，回報失敗軌跡（見升降級規則）。
```

## 範本 3：重構

```
任務：把 ＜對象＞ 重構為 ＜目標形態＞，行為不得改變。
動機：＜為什麼值得重構＞。
安全網：動手前先確認 ＜測試命令＞ 全綠並記錄基準；沒有測試就先為受影響路徑補
最小煙霧測試，或降級為「只搬移不改寫」。
範圍：＜檔案清單＞；不做行為變更、不做順手優化。
驗收條件：
- 重構前後 ＜測試命令＞ 結果一致（全綠→全綠）。
- ＜舊介面／舊名稱＞ 的所有呼叫點都已更新（用搜尋證明為 0 殘留）。
回報格式：驗收逐條 ✅/❌ ＋ 前後測試輸出 ＋ 呼叫點更新清單（檔案:行號）。
```

## 範本 4：研究／查證

```
任務：查證 ＜問題清單，逐條編號＞。
動機：＜這些答案會被用來做什麼決定＞。
方法：用當前網路來源查證，不憑訓練記憶回答；每個事實附來源 URL；
查不到的寫「UNVERIFIED」，禁止猜測補洞。
驗收條件：
- 每個編號問題都有「FACT + 來源」或「UNVERIFIED + 你試過的查法」。
- 相互矛盾的來源要並列並標明何者較可信、為什麼。
回報格式：逐題作答 ＋ 結尾一張摘要表。長內容存檔回傳路徑。
```

## 範本 5：審查（code review／文件對抗審查）

```
任務：審查 ＜對象：diff／檔案清單＞，你沒有參與撰寫，請以敵對視角找問題。
動機：＜這份東西將被用於什麼場景＞。
審查清單（逐項檢查並回報）：
- 正確性：會在什麼輸入／狀態下出錯？給出具體觸發情境。
- 一致性：內部規則有沒有互相打架？名詞是否前後同義？
- 可執行性：一個沒有背景的執行者照著做，會卡在哪一步？
- 事實性：型號、路徑、旗標、命令是否可疑（過期／編造）？標出需查證項。
驗收條件：每個發現都有「位置（檔案:行號）＋ 問題一句話 ＋ 觸發情境或修法」。
沒有發現也要逐項回報「檢查過、無問題」，不許整體一句「LGTM」。
回報格式：發現清單按嚴重度排序；≤15 條，超過就只回最嚴重的 15 條。
```
